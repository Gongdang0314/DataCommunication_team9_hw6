======================================================================
 HW#6 Mini-Torrent — 9조 AllDefinedLogs.txt
 우리 프로그램(tracker.py · peer.py)이 실제로 남기는 모든 이벤트(ev)와 필드
======================================================================

형식 : ev  필드...  : 언제 (누가)
공통 : {"t": 그 프로그램 시작 후 초(소수 2자리), "peer": 쓴 프로그램(P1~P4 | tracker), "ev": 이름, ...필드}
       - 컴포넌트마다 파일 하나: logs/P1.jsonl ~ logs/P4.jsonl, logs/tracker.jsonl (VM 에서 scp 로 가져옴)
       - 한 줄 = JSON 객체 하나, 일이 일어난 그 순간 기록 후 바로 flush (키트 lib/evlog.py, lock 하나)
       - 필드 이름으로 t · peer · ev 는 쓰지 않는다. 상대 Peer 는 target · src · id 로 쓴다
       - 숫자는 숫자로, ok 는 true/false. ASCII 막대 · 화면용 문장은 jsonl 에 넣지 않는다 (화면에만)
       - 마지막 줄은 항상 EXIT (파괴된 희생자도 DESTROY 다음 EXIT code=3)
       - ★ = 과제명세서 9-3 의 필수 이벤트


[Peer]  logs/<id>.jsonl

★START     env run policy up_kbps down_kbps rng_seed tracker workers per_peer_max
           : env 를 읽은 직후 첫 줄 (main). tracker = "IP:PORT" (실행 인자), rng_seed = policy_seed + 피어 번호
 HASH      file ok sec [origin]
           : 원본 seed 의 시작 시 SHA-256 확인 (origin=true), 또는 받은 파일의 마지막 청크를 쓴 직후 비교 (worker)
 GET       file chunks
           : 받을 파일 하나를 시작할 때 (.part 를 전체 크기로 만든 뒤, main)
★RECV      file idx src
           : 청크 하나를 pwrite 하고 bit 를 1 로 바꾼 직후, 청크마다 한 줄 (worker). src = 보낸 Peer
 RETRY     file idx src err
           : (우리 조 추가) 재사용하던 연결이 낡아 끊겨 있으면(상대가 crash 에서 돌아옴 등) 새 연결로 한 번 다시 보냄.
             RETRY 는 실패로 세지 않는다. 새 연결도 실패하면 FAIL
 FAIL      file idx src err
           : GET 실패 (worker). err = ConnClosed | ConnectionRefused | timeout | ERR NOCHUNK | ValueError(헤더 오류)
             crash 중이라 내가 버린 요청은 상대 탓이 아니므로 FAIL 로 남기지 않는다
 BAN       target sec
           : 같은 상대에게 연속 fail_limit(3) 번 실패한 순간 -> ban_sec(5) 초 동안 그 상대에게 요청하지 않음 (worker)
 COMPLETE  file sec sources
           : HASH ok=true -> .part 를 원래 이름으로 rename 한 직후 (그 뒤 Tracker 에 REGISTER). sec = 그 파일 받는 데 걸린 시간,
             sources = {보낸 Peer: 청크 수}
 CORRUPT   file action tries
           : HASH 불일치. action = redownload(1회: bitmap 을 0 으로 하고 처음부터) | give_up(2회 연속: .corrupt 로 남기고 FAILED)
★CRASH     sec
           : HEARTBEAT 응답 CMD DISCONNECT <sec> 를 받아 사라지는 순간 (control). 이때부터 sec 초 동안 아무것도 보내지 않는다
★REJOIN    (없음)
           : sec 초 뒤 스스로 돌아와 listen -> HELLO -> REGISTER/HAVE 를 다시 보낸 직후
★DESTROY   (없음)
           : HEARTBEAT 응답 CMD DESTROY 를 받은 순간 (결과 저장 전). 그 뒤 결과 저장 -> EXIT code=3, BYE 없음
★STALLED   file lost
           : 받는 파일의 남은 청크 전부가 rarity 0 인 상태가 stall_sec(30) 초 계속됨 (control). lost = 못 받은 청크 수
 UNSTALLED file
           : STALLED 파일에 받을 수 있는 청크가 다시 생김 (control)
★DONE      kind detail
           : 받는 파일이 모두 SEED/STALLED/FAILED 가 되어 Tracker 에 DONE 을 보낸 직후 (control).
             kind = FULL | PARTIAL, detail = "share30.bin:169" (STALLED 파일:남은 수, FAILED 면 파일:FAILED), FULL 이면 ""
 UNDONE    (없음)
           : DONE 뒤 다시 받을 것이 생겨 Tracker 에 UNDONE 을 보냄 (control)
 ALLDONE   done alive
           : STATE 응답에서 ALLDONE 을 본 순간 (control) -> 정상 종료 절차 시작
 ABORT     reason [silent_sec]
           : STATE ... ABORT <reason>(stalled | deadline) 을 봤거나, Tracker 응답이 tracker_lost_sec(30) 동안 없음
             (reason=tracker_lost, silent_sec = 마지막 응답 뒤 지난 초. 가상 crash 시간은 빼고 잰다) -> exit 2
★EXIT      code up_mb down_mb [reason]
           : 마지막 줄. 결과 파일 저장 · BYE 뒤 (destroy 는 저장 뒤 BYE 없이).
             code = 0 정상(ALLDONE) | 1 설정 오류(원본 SHA-256 불일치 등, reason 포함) | 2 ABORT · tracker_lost | 3 파괴된 희생자
             up_mb / down_mb = 이 Peer 가 보낸 / 받은 청크 데이터 양 (MB, 1 MB = 1,048,576 B)


[Tracker]  logs/tracker.jsonl   (t 는 Tracker 시작 후 초. START 줄의 t 를 빼면 report.json 과 같은 START 기준)

★START_PROGRAM env run port
           : listen 을 시작한 직후 첫 줄
 JOIN      id n src_ip
           : 처음 HELLO 를 보낸 Peer (n = 참가 순서, src_ip = 연결에서 본 주소 — PEERS 응답에는 쓰지 않는다)
★START     peers
           : env 의 Peer 4명이 모두 HELLO 한 순간 — crash 일정 · destroy 시각 · report.json 시각의 기준(0초)
 REGISTER  id file src_ip
           : REGISTER 를 받음 (원본, 또는 완성한 파일 -> 이제 그 파일의 seed). crash 에서 돌아와 다시 등록할 때도 남는다
 REJOIN    id
           : 이미 참가했던 Peer 의 HELLO (가상 crash 복귀)
★CMD       target cmd sec | progress
           : scheduler 가 지시를 pending 에 넣은 순간. cmd = DISCONNECT(sec 포함) | DESTROY(progress = 그때 전체 진행률)
 CMD_DELIVERED id cmd
           : 그 Peer 의 HEARTBEAT 응답으로 실제로 보낸 순간 (cmd = 보낸 문자열, 예 "CMD DISCONNECT 6.4")
 CMD_DROPPED id cmd
           : ALLDONE · ABORT 뒤라 보내지 않고 버린 지시 (report.json crashes_sent 에서도 뺀다)
★DEAD      id silent_sec
           : 그 Peer 의 메시지가 dead_sec(20) 동안 없음 (scheduler 0.5초) -> PEERS · ALLDONE 계산에서 제외
 BACK      id
           : DEAD 였던 Peer 에게서 다시 메시지가 옴
 REPLICATED file t_start upstat progress
           : observer(1초) — 원본 보유자를 뺀 Peer 들의 bitmap OR 가 처음 100% (T_rep). t_start = START 기준 초,
             upstat = 그 순간 원본 보유자의 [sent, distinct], progress = 그때 전체 진행률
 ALL_REPLICATED t_start p_rep
           : 모든 파일이 T_rep 에 도달한 순간 (p_rep = 그때 진행률, after_replication trigger 의 기준)
 DONE      id kind detail
           : Peer 의 DONE 을 받음
 UNDONE    id
           : Peer 의 UNDONE 을 받음
★ALLDONE   live done
           : live Peer 전원이 DONE 임을 확인한 순간 (live = 명단, done = {id: kind})
 ABORT     reason progress
           : 전체 진행률이 hang_sec(60) 동안 그대로(reason=stalled) 또는 deadline_sec(900) 초과(reason=deadline)
 BYE       id
           : Peer 의 BYE 를 받음 (정상 퇴장)
★EXIT      code alldone t_exit
           : report.json 을 쓴 뒤 마지막 줄. code = 0 | 2(ABORT), alldone · t_exit = START 기준 초


[report.json]  (Tracker 가 종료할 때 한 번, 들여쓰기 2칸, 시각은 모두 START 기준 초)
  env run seed policy destroy_plan crashes_sent T_rep p_rep upstat_at_rep dup_ratio T_destroy p_destroy
  T_dead T_done T_last_done T_alldone T_exit done_kind peers abort
  - 일어나지 않은 일은 null. peers 값 = BYE | DEAD | NO_BYE


[Peer 결과 파일]  pN/
  <file>.bitmap      모든 Peer × 모든 파일, 종료 직전 ('0'/'1' 문자열, 청크 수만큼, 줄바꿈 없음)
  <file>.lost        다 받지 못한 파일만 (빠진 청크 번호 오름차순, 쉼표, 연속 구간 a-b)
  <file>.incomplete  다 받지 못한 파일만 (.part 의 이름을 바꾼 데이터 파일 — verify 용, 제출 안 함)
  <file>             완성 파일 (제출 안 함)
